# 3D effects

A 3D effect is an ordinary effect file (`src/fx/<category>/<name>.js`, the contract in [AUTHORING.md](AUTHORING.md))
that draws in world space through a camera. It is still pixel art: every pixel lands on the same grid, with the same
two buffers (color and light), the same palettes and the same dither. What 3D adds is a depth for every pixel, so
the effect sorts itself around a character and looks right from any side.

Every effect in the library comes in 3D. The ones in `src/fx/3d/` are 3D only. Every other effect is 2D and also
exports a **3D variant** in the same file, `<id>@3d` to the tools and the gallery (`fire/torch` and `fire/torch@3d`).

Worked examples: `3d/orbit-orbs.js` (a pure loop around a character), `3d/shockwave.js` (a simulation on the floor),
`3d/whirlwind.js` (a slash in a plane, with an act), `3d/meteor.js` (perspective, fire that lands), and
`fire/torch.js`'s `three` (a 2D effect's variant that reuses its 2D drawing).

## Make an effect 3D

1. Give its meta a camera: `camera: { pitch: 0.3 }`. That is what makes it 3D: the tools render it from other angles,
   the gallery lets you drag it round, and frames get a depth buffer.
2. Draw through a Space: `const q = space(p, o)` in `draw(p, t, o)`, or in `create(o)`'s `draw(p)`. `q` takes world
   coordinates; `p` is still there for 2D work.
3. `bg: "ground"` shows a floor that turns with the camera instead of the 2D brick floor.

`node tools/new.mjs <category>/<name> --3d` (add `--loop`) writes a working starting point.

## Give a 2D effect its 3D variant

Export `three` next to the 2D effect, in the same file. The 2D exports stay exactly as they are: games that use the 2D
effect see no change.

```js
export const three = {
  meta: { size: [112, 140], origin: [56, 118], bg: "ground", camera: { pitch: 0.28 } },   // laid over the 2D meta
  draw(p, t, o) { const q = space(p, o); /* ... */ },                                      // or create(o)
  // act, actorAlpha: the 2D effect's are used unless you give your own. drawBack isn't: depth sorts a 3D draw
};
```

`in3d(mod)` turns a module into its 3D variant as an effect of its own; the tools and the gallery do this for every
`<id>@3d`. The variant's options are the 2D options with its own on top, so palettes and seeds carry over.

Build it from three kinds of part, chosen by how each part of the 2D effect would really sit in space:

- **The same from every side** (a flame, a glow, an orb, a star, a spark's head, a floating number, a portal seen
  face on): draw it with the 2D helpers it already has, upright, with `q.at(x, y, z, (p, k) => ...)`. That is how
  3D games draw flames and glows too, and it keeps the pixel art the effect was drawn with.
- **Flat on something** (a ring, a rune circle, a scorch, a puddle, cracks, a shadow, a slash on a tilted plane, a
  shockwave on the floor): draw it in 2D, as if looking straight at it, and lay it down with
  `q.decal(cx, cy, cz, n, R, (p) => ...)`. A 2D effect's squashed floor ellipse becomes a plain circle in the decal.
- **Spread out in space** (particles, debris, sparks, smoke, rays, bolts, projectiles' paths, beams, lines between
  things): give it real positions in x, y and z. `spawn3`, `q.line`, `q.beam`, `q.ball`, `q.ring` and `q.arc`, and
  closed-form motion with a z for pure effects.

A 2D effect whose particles fly left and right sends them out in a full circle in 3D. Something that faces right in
2D faces +x in 3D, so turning the camera shows it from the side and behind. Keep the effect's timing, palette, phases
and light from the 2D version: the 3D variant is the same effect, standing in space.

## World space and the camera

- x right, y down (the floor is y = 0, up is negative y, as in 2D), z towards the viewer at yaw 0. 1 unit = 1 px.
- `meta.camera` (and `o.camera` at runtime, which overrides it): `yaw` (radians; the camera orbits right as it grows),
  `pitch` (radians above the floor: 0.3 shows a floor circle as an ellipse 0.3 tall), `dist` (px from the origin for
  perspective; leave it out for orthographic, the usual pixel art look), `zoom`, and `at` (`[x, y, z]`, where the
  effect's origin sits in a bigger scene; `chain` sets it for the cues of a 3D move).
- From yaw 0, pitch 0, a Space draws exactly what the 2D painter would at z = 0. So 2D shape code ports by giving
  it a z.
- Depth is a number per pixel, smaller is nearer, 0 on the plane through the origin facing the camera. A 2D
  character drawn by the tools stands at depth 0: the far half of a ring goes behind him and the near half in front,
  with no `drawBack`.

## The Space

| call | draws |
|---|---|
| `q.px(x, y, z, c)`, `q.dot(x, y, z, c, a)`, `q.blend`, `q.light` | one pixel, solid, dithered, translucent, light |
| `q.line(x0, y0, z0, x1, y1, z1, c, a)`, `q.polyline([[x, y, z], ...], c, a)` | 1 px lines with depth along them; c, a may be `(u) =>` |
| `q.ball(x, y, z, r, c, a)` | an opaque sphere, a depth per pixel; c may be `(nx, ny, nz) =>` of its normal, `lit(ramp)` shades it |
| `q.disc(x, y, z, r, c, a)` | a translucent puff (smoke, vapour) that thins into what is in front of it |
| `q.beam(x0, y0, z0, x1, y1, z1, w, c, a)` | a capsule; c, a may be `(u, v) =>` |
| `q.glow(x, y, z, r, c, k)`, `q.glowLine(...)` | light that lights what lies within r of it, hidden by anything solid already drawn further in front |
| `q.plane(cx, cy, cz, n, R, fn, bias)` | a pixel shader on a disc of radius R in any plane: `fn(u, v, out)` like `p.shade`, plus `out.blend`; `bias` pushes a backdrop's depth back |
| `q.ring(cx, cy, cz, r, w, c, a, n)` | a ring, a true circle, in a plane (default the floor) |
| `q.arc(cx, cy, cz, r, w, a0, a1, c, a, n)` | a band of a ring in any plane: slashes and smears; w may taper with u |
| `q.at(x, y, z, (p, k) => ...)` | any 2D drawing as a billboard at that point and depth; k is px per unit there; lower `p.z` inside to bring a part forward |
| `q.decal(cx, cy, cz, n, R, (p) => ...)` | any 2D drawing laid flat on a plane (default the floor) within radius R: on the floor 2D y runs towards the viewer at yaw 0; thin lines survive the squash |
| `q.project(x, y, z)`, `q.depth(x, y, z)`, `q.sort(items, pos)` | where a point lands (`q.x q.y q.d q.k`), its depth, items far to near |

In a plane, angles run from u towards v. On the floor (`n` left out) u is x and v is z. On a plane facing the viewer
(`n = [0, 0, 1]`) u is x and v is y, so a 2D `p.arc` becomes `q.arc(..., [0, 0, 1])` and can then be tilted.

`lit(ramp, light?)` shades a ball in hard ramp steps from a light at the top left and in front, darkest on the rim.

## Particles, debris and lights in 3D

The toolkit in `src/core/sim.js` works in 3D as it is:

- `ps.spawn3(kind, x, y, z, vx, vy, vz, life, color, size, delay, flags)`; z drifts, drags and sways like x.
  `ground: (x, z) => y` and `onLand(x, y, z)` get z.
- `bits.add({ ..., z, vz })`, `lights.add(x, y, r, color, k, life, z)`, `blazes.add(x, y, life, power, z)`.
- Pass the Space to draw: `ps.draw(q)`, `bits.draw(q)`, `lights.draw(q)`, `blazes.drawBack(q)`. Particles sort
  themselves: solid kinds nearest first, then smoke and vapour far to near, each as thick as it is big so one lying on
  the floor doesn't sink into it. Layers ("back", "front") don't apply in 3D.

## Depth rules

- Opaque pixels write depth; translucent pixels and light only test it against what is already there. So draw
  solid things first, nearest first, then light, then translucent things far to near (`q.sort`). Particle systems
  already do; `orbit-orbs.js` shows the order by hand.
- 2D drawing into a 3D frame happens at depth 0 (`p.z`); every Space call leaves `p.z` as it found it. `q.at` moves
  2D drawing to a point's depth.
- The preview floor (`floorGrid`) sits a little behind y = 0, so cracks, embers and settled debris on it stay visible.
- Size the canvas for every side: `tools/check.mjs` renders 8 directions and warns when any of them spills.

## Acts

A 3D effect can have an act like any other. The body and the target stand at depth 0 and the effect sorts round
them, so a spin really goes behind him and comes back in front. `whirlwind.js` reuses the 2D spin slash's act.

## Moves

`chain` works in 3D. Give the move a camera and each cue a place in its space with `x`, `y` and `z` (numbers or
functions of time). A 3D cue shares the move's camera, with its origin moved there (`camera.at`), so depth and
perspective line up across the cues. A 2D cue stands upright at that point and its depth, like a billboard
(`o.depth` places any 2D effect at a depth in a 3D frame).

```js
export const meta = { /* ... */ camera: { pitch: 0.4 } };
export const create = chain([
  { fx: shockwave, t: 0, z: 30 },
  { fx: orbitOrbs, t: 0, x: -40, z: -20 },
  { fx: hitFlash, t: 0.2, x: 40, y: -12, z: -30 },   // a 2D effect, as a billboard
]);
```

## Look at it

- `node tools/render.mjs <id>` writes `contact.png` from the effect's own camera and `views.png`: the same moments
  from 8 directions, one row each. Judge both. A 3D effect that is right from the front and flat from the side
  isn't done.
- `--yaw DEG --pitch DEG --dist PX` render from another camera.
- `node tools/orbit.mjs <id>` plays it on repeat while the camera goes once round (GIF, or `--mp4`).
- The gallery (`node tools/serve.mjs`) turns 3D effects slowly; drag one, or use the arrow keys, to turn it yourself.

## Put it in a game

**A JS engine (three.js, Babylon, a canvas game).** Play it live with the game's camera. Create the frame with a depth
buffer, give the effect the camera's angle to it every frame, and draw the frame on a camera-facing quad at the
effect's position, a pixel per unit:

```js
import { createFrame, clearFrame, createFx, composite, cameraToward } from "dotspace";
import * as shockwave from "dotspace/fx/3d/shockwave";

const frame = createFrame(184, 124, 0, 0, true);
const fx = createFx(shockwave, { x: 92, y: 82 });
// every tick: the direction from the effect to the eye, in an engine with y up and the camera looking down -z
const d = camera.position.clone().sub(effectPosition);
Object.assign(fx.options.camera, cameraToward(d.x, d.y, d.z));
fx.update(dt);
fx.draw(clearFrame(frame));
composite(frame, texture.image.data, null);
```

**Any engine (Godot, Unity, Unreal, Bevy).** Bake it. `node tools/render.mjs <id> --sheet --views 8` writes one row
per direction, with a frame tag each (`<name>@yaw0`, `<name>@yaw45`, ...) and `meta.dotspace.views` (each row's yaw
and pitch). Play it on a billboard (Godot's `Sprite3D` or `AnimatedSprite3D` with billboard on) and pick the row
nearest the angle between the camera and the effect: `cameraToward` does that sum, and the yaw of row i is
`i * 360 / views` degrees.

**Lit by the scene.** Add `--maps` to also write, laid out like the sheet:

- `<name>.albedo.png`: color without glow. Use it as the material's albedo.
- `<name>.emission.png`: glow alone, black where none. Use it as emission (unshaded, additive).
- `<name>.normal.png`: a tangent-space normal map, green up (OpenGL, as Godot and three.js read it). Solid pixels
  bend with their depth, translucent and 2D pixels bulge with their alpha, so smoke and flat sprites shade round.
- `<name>.depth.png` (3D effects): white near, black far, alpha 0 where nothing solid; `meta.dotspace.depth` has the
  range in px. Use it for soft particles or depth offsets.

`--maps` works for 2D effects too, so any of the library's effects can stand in a lit 3D scene.
